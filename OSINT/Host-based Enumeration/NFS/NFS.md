NFS

Сетевая файловая система

Ее цель — доступ к файловым системам по сети, как если бы они были локальными

клиенты NFS не могут напрямую взаимодействовать с серверами SMB





+----------------+-----------------------------------------------------------------------------------------------------------------------------------------------+

| Версия         | Функции                                                                                                                                       |

+----------------+-----------------------------------------------------------------------------------------------------------------------------------------------+

| NFSv2          | Это более старая технология, но она поддерживается многими системами и первоначально работала исключительно по протоколу UDP.                 |

| NFSv3          | Она обладает расширенными функциями, включая переменный размер файлов и улучшенную систему сообщений об ошибках, но не полностью совместима с клиентами NFSv2. |

| NFSv4          | Она включает Kerberos, работает через межсетевые экраны и в интернете, больше не требует портмапперов, поддерживает списки контроля доступа (ACL), применяет операции на основе состояния, а также обеспечивает повышение производительности и высокий уровень безопасности. Это также первая версия с протоколом, учитывающим состояние. |

+----------------+-----------------------------------------------------------------------------------------------------------------------------------------------+





/etc/exports

содержит таблицу физических файловых систем на NFS-сервере, доступных клиентам

Таблица экспорта NFS показывает, какие параметры она принимает, и, следовательно, 

указывает, какие параметры доступны





Экспорт файла

SavitskiyES@htb\[/htb]$ cat /etc/exports 



\# /etc/exports: the access control list for filesystems which may be exported

\#               to NFS clients.  See exports(5).

\#

\# Example for NFSv2 and NFSv3:

\# /srv/homes       hostname1(rw,sync,no\_subtree\_check) hostname2(ro,sync,no\_subtree\_check)

\#

\# Example for NFSv4:

\# /srv/nfs4        gss/krb5i(rw,sync,fsid=0,crossmnt,no\_subtree\_check)

\# /srv/nfs4/homes  gss/krb5i(rw,sync,no\_subtree\_check)

















В файле по умолчанию exports + содержатся примеры настройки общих ресурсов NFS. 

Сначала указывается папка и предоставляется доступ другим пользователям

затем права доступа к этой общей папке NFS связываются с хостом или подсетью

И можно добавить дополнительные параметры для хостов или подсетей.





+-------------------+-----------------------------------------------------------------------------------------------------------------------------------------------+

| Вариант           | Описание                                                                                                                                      |

+-------------------+-----------------------------------------------------------------------------------------------------------------------------------------------+

| rw                | Права доступа на чтение и запись.                                                                                                             |

| ro                | Доступ только для чтения.                                                                                                                     |

| sync              | Синхронная передача данных. (Немного медленнее)                                                                                               |

| async             | Асинхронная передача данных. (Немного быстрее)                                                                                                |

| secure            | Порты с номерами выше 1024 использоваться не будут.                                                                                           |

| insecure          | Будут использоваться порты с номерами выше 1024.                                                                                              |

| no\_subtree\_check  | Этот параметр отключает проверку структуры подкаталогов.                                                                                      |

| root\_squash       | Назначает все права доступа к файлам корневого пользователя с UID/GID 0 пользователю с UID/GID, что предотвращает root-доступ к файлам на смонтированной NFS-системе. |

+-------------------+-----------------------------------------------------------------------------------------------------------------------------------------------+









##### ExportFS

##### (создание записи для теста настроек)



root@nfs:~# echo '/mnt/nfs  10.129.14.0/24(sync,no\_subtree\_check)' >> /etc/exports

root@nfs:~# systemctl restart nfs-kernel-server 

root@nfs:~# exportfs



/mnt/nfs      	10.129.14.0/24



Предоставляем доступ к папке /mnt/nfsв подсети 10.129.14.0/24 с указанными выше настройками 

Это означает, что все хосты в сети смогут монтировать этот NFS-ресурс и просматривать содержимое этой папки.











##### Опасные условия



при использовании NFS некоторые настройки могут быть опасны 

для компании и её инфраструктуры. Вот некоторые из них:





+----------------+-----------------------------------------------------------------------------------------------------------------------------------------------+

| Вариант        | Описание                                                                                                                                      |

+----------------+-----------------------------------------------------------------------------------------------------------------------------------------------+

| rw             | Права доступа на чтение и запись.                                                                                                             |

| insecure       | Будут использоваться порты с номерами выше 1024.                                                                                              |

| nohide         | Если в экспортируемый каталог была смонтирована другая файловая система, то этот каталог экспортируется с помощью собственной записи в реестре. |

| no\_root\_squash | Все файлы, созданные пользователем root, хранятся с UID/GID 0.                                                                                |

+----------------+-----------------------------------------------------------------------------------------------------------------------------------------------+

Как только мы обнаружим такую ​​службу NFS, мы сможем смонтировать 

её на нашем локальном компьютере м перемещаться по ней





SavitskiyES@htb\[/htb]$ showmount -e 10.129.14.128



Export list for 10.129.14.128:

/mnt/nfs 10.129.14.0/24









Подключение NFS-ресурса



SavitskiyES@htb\[/htb]$ mkdir target-NFS

SavitskiyES@htb\[/htb]$ sudo mount -t nfs 10.129.14.128:/ ./target-NFS/ -o nolock

SavitskiyES@htb\[/htb]$ cd target-NFS

SavitskiyES@htb\[/htb]$ tree .



.

└── mnt

&nbsp;   └── nfs

&nbsp;       ├── id\_rsa

&nbsp;       ├── id\_rsa.pub

###### для просмотра файлы. Как только у нас появятся имена пользователей, 

###### имена групп, UID и GUID, мы сможем создать их в нашей системе и адаптировать 

###### к общему ресурсу NFS для просмотра и изменения файлов

Можем использовать NFS для дальнейшего повышения уровня доступа. 

Например, если есть доступ к системе через SSH и хотим прочитать 

файлы из другой папки, доступной определенному пользователю, нам 

потребуется загрузить оболочку в общий ресурс NFS, содержащий учетные 

данные SUID этого пользователя, а затем запустить эту оболочку 

через пользователя SSH

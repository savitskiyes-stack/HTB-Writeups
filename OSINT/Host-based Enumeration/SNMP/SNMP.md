SNMP



Simple Network Management Protocol (https://datatracker.ietf.org/doc/html/rfc1157)

Протокол SNMP был создан для мониторинга сетевых устройств



Текущая версия — SNMPv3, которая повышает безопасность SNMP в частности,

но также и сложность использования этого протокола







SNMP передает команды управления с помощью агентов через UDP-порт 161



В то время как в классической связи клиент всегда активно запрашивает информацию у сервера, SNMP также позволяет использовать так называемый trapsUDP-порт 162. Это пакеты данных, отправляемые с SNMP-сервера клиенту без явного запроса









MIB — это независимый формат для хранения информации об устройстве. MIB представляет собой текстовый файл, в котором все доступные для запроса объекты SNMP устройства перечислены в стандартизированной древовидной иерархии

Он содержит как минимум один Object IdentifierMIB ( OIDMicrosoft Data Exchange), который, помимо необходимого уникального адреса и имени, также предоставляет информацию о типе, правах доступа и описании соответствующего объекта







OID представляет собой узел в иерархическом пространстве имен. Последовательность чисел однозначно идентифицирует каждый узел, позволяя определить его положение в дерев

Протокол SNMP версии 1 ( SNMPv1) используется для управления и мониторинга сети. SNMPv1 — первая версия протокола, которая до сих пор используется во многих небольших сетях

###### Опасные условия

К числу опасных настроек, которые администратор может установить в SNMP, относятся:



Настройки

+-----------------------------+--------------------------------------------------------------------------------+

| Настройка                   | Описание                                                                       |

+-----------------------------+--------------------------------------------------------------------------------+

| rwuser noauth               | Предоставляет доступ ко всему дереву OID без аутентификации.                   |

| rwcommunity <community string> <IPv4 address> | Предоставляет доступ ко всему дереву OID независимо от того, |       |                             |                                                                                |

|                             | откуда были отправлены запросы.                                                |

| rwcommunity6 <community string> <IPv6 address> | Доступ такой же, как и раньше, rwcommunity с той разницей, что      |                             |                                                                                |

|                             | используется IPv6.                                                             |

+-----------------------------+--------------------------------------------------------------------------------+









Создание базы данных для сервиса



Для сбора информации о SNMP-сообщениях можно использовать такие инструменты, как snmpwalk, onesixtyone, и braa. Snmpwalk



Onesixtyoneможет использоваться для подбора имен строк сообщества методом перебора, поскольку администратор может произвольно их называть

















SNMPwalk



SavitskiyES@htb\[/htb]$ snmpwalk -v2c -c public 10.129.42.195



 

















Если неизвестна строка сообщества, мы можем использовать onesixtyone списки SecLists слов для идентификации этих строк сообщества



OneSixtyOne

SavitskiyES@htb\[/htb]$ sudo apt install onesixtyone







если мы представим себе обширную сеть с более чем 100 различными серверами, управляемыми с помощью SNMP, метки в этом случае будут иметь определенный шаблон. Следовательно, мы можем использовать различные правила для их угадывания. Мы можем использовать инструмент crunch для создания пользовательских списков слов







Получив доступ к строке сообщества, мы можем использовать её с помощью Braa для перебора отдельных OID и получения информации, стоящей за ними



Braa

SavitskiyES@htb\[/htb]$ sudo apt install braa

SavitskiyES@htb\[/htb]$ braa <community string>@<IP>:.1.3.6.\*   # Syntax

SavitskiyES@htb\[/htb]$ braa public@10.129.14.128:.1.3.6.\*

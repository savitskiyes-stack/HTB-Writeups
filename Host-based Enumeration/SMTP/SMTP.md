SMTP
протокол для отправки электронных писем в IP-сети
Протокол типа клиент - сервер, но может также двумя SMTP серверами


По умолчанию порт 25
Более новые версии используют 587 ( Этот порт используется для приема почты от аутентифицированных пользователей/серверов, обычно с помощью команды STARTTLS для переключения существующего соединения в открытом виде на зашифрованное)



Важнейшая функция SMTP-сервера — предотвращение спама с помощью механизмов аутентификации, позволяющих отправлять электронные письма только авторизованным пользователям. Для этой цели большинство современных SMTP-серверов поддерживают расширение протокола ESMTP с SMTP-Auth

У протокола SMTP есть два недостатка


1. Во-первых, отправка электронного письма по протоколу SMTP не возвращает корректное подтверждение доставки. Хотя спецификации протокола предусматривают такой тип уведомления, его формат по умолчанию не указан, поэтому обычно возвращается только сообщение об ошибке на английском языке, включая заголовок недоставленного сообщения

2. При установлении соединения пользователи не проходят аутентификацию, поэтому отправитель электронного письма считается ненадежным. В результате открытые SMTP-серверы часто используются для массовой рассылки спама. Отправители используют для этой цели произвольные поддельные адреса отправителей, чтобы их не удалось отследить (подмена почты). Сегодня для предотвращения злоупотреблений SMTP-серверами используется множество различных методов обеспечения безопасности. Например, подозрительные электронные письма отклоняются или перемещаются в карантин (папку спама). Например, за это отвечают протокол идентификации DomainKeys ( DKIM) и Sender Policy Framework ( SPF).

Для решения было разработано расширение для SMTP, называемое Extended SMTP( ESMTP). Когда люди говорят о SMTP в целом, они обычно подразумевают ESMTP. ESMTP использует TLS, который выполняется после команды EHLOпутем отправки STARTTLS

Опасные условия
Чтобы предотвратить попадание отправленных писем в спам-фильтры и их потерю для получателя, 
отправитель может использовать ретрансляционный сервер, которому доверяет получатель. 
Это SMTP-сервер, известный и проверенный всеми остальными. Как правило, отправитель 
должен пройти аутентификацию на ретрансляционном сервере, прежде чем использовать его.

Зачастую администраторы не имеют представления о том, какие диапазоны IP-адресов им 
необходимо разрешить. Это приводит к неправильной настройке SMTP-сервера, которую мы 
часто обнаруживаем при внешних и внутренних тестах на проникновение. Поэтому они 
разрешают все IP-адреса, чтобы избежать ошибок в почтовом трафике и, таким образом, 
не мешать или непреднамеренно прерывать связь с потенциальными и существующими клиентами.

mynetworks = 0.0.0.0/0




При таких настройках этот SMTP-сервер может отправлять поддельные электронные письма и, 
таким образом, инициировать обмен данными между несколькими сторонами. Другой вариант 
атаки — подделать электронное письмо и прочитать его
